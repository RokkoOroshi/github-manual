## はじめに
全部員向けマニュアルが全て理解したうえで、gitをそこそこ利用してチーム、権限などについて、大まかな知識はあり、その上で一般的な情報技術に関する知識があるということを前提に書きます。

## 概要
管理者としてorganizationアカウントの運営を行うためのマニュアルである。
メンバーが安全・円滑に活動できる環境を整えることが管理者の主な役割となる。

## 管理方法
### メンバー管理
organizationページの「People」タブからメンバーの招待・削除を行う。
* 招待はGitHubのユーザー名またはメールアドレスで行う
* 招待されたメンバーはメールで通知を受け取り、承認することで参加できる
* 退部者はすみやかにorganizationから削除すること

### 権限管理
チーム機能を活用してロボット班ごとに権限を設定する。
* organizationページの「Teams」タブからチームを作成し、メンバーとリポジトリを紐付ける
* 各チームへの権限は `Read / Triage / Write / Maintain / Admin` の5段階で設定できる
* 原則として必要以上の権限は与えない（詳細は資料のrole一覧を参照）

### リポジトリ管理
* 新しいリポジトリはorganization配下に作成する
* 作成時にREADMEを必ず生成すること
* 公開設定は原則publicとする（個人情報を含む場合のみprivate）
* mainブランチへの直接pushを禁止するブランチ保護ルールの設定を推奨する
    * 各リポジトリページ > Settings > Branches から設定できる

### プロジェクト管理
* GitHub Projectsを活用してタスクの進捗を可視化できる
* IssuesでバグやTODOを管理し、Pull Requestと紐付けることで変更の追跡がしやすくなる

## 資料
### role一覧
GitHubのorganizationにおけるroleは **Owner / Member** の2種類のみ。
ロボット班ごとの細かい権限はTeams機能で別途設定する。

**Organization role**
| ロール | 対象 | 権限 |
|---|---|---|
| Owner | 管理者（最小限の人数） | organization全体の設定変更・メンバー追加削除・リポジトリ作成削除が可能 |
| Member | 一般部員 | 招待されたリポジトリへのアクセスのみ（権限はTeamsで制御） |

Ownerは権限が非常に強いため、必要最低限の人数に絞ること。

**Teams によるリポジトリ権限（各ロボット班）**
| チーム | リポジトリ | 権限 |
|---|---|---|
| 各ロボット班 | 自分の班のリポジトリ | Write |
| 各ロボット班 | 他班のリポジトリ | Read |

Teamsの権限は `Read / Triage / Write / Maintain / Admin` の5段階で設定できる。

## 管理者として注意するべきこと
* 権限を与えすぎないこと
    何か起こってからでは遅いです。
> ※ チーム機能を上手く使おう！
* マニュアルには必ず適宜スクショを貼ること。
    面倒かもしれないが、知識のない人間というのは文面から全てを理解することはできません。
* できるだけpublicに
    我々は営利目的ではありません、方針として外部公開を積極的に
    しかし、個人情報などには気を付けて
* 新技術には積極的に
    adminになっているということは君はほぼ部のCIOだよ。導入提案は積極的に

## 部員に周知するべきこと
* READMEは必ず書くこと
    * プロジェクトの概要・環境構築手順・使い方を記載する
    * 「読んだだけで動かせる」レベルを目標にする
* ファイル名、ディレクトリ名は必ず意味のある名前をつけること
    * `temp`・`test2`・`新しいフォルダ`などは禁止
    * 何が入っているか名前だけで判断できるようにする
* コメントは必ず書くこと
    * 一か月前の自分のコードは他人のコードです。
* push,commitは頻繁に
    * ロールバック機能は便利です。
    * コミットしないと誰も参照できません。
* コーディング規約を守らせよう
    * まだできていないが、今後作りたい。
